# Futaba v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 書くまで0秒のアイデア帳 Futaba を、Android アプリと Chrome 拡張として v1 リリースする。

**Architecture:** Android は単一モジュール（`:app`）の Compose アプリで、パッケージは機能ごと（`feature/*`）と共通（`core/*`）に分ける。Firestore の永続キャッシュを手元の正本とし（Room なし）、`users/{uid}/notes` を snapshot で購読、絞り込み・検索はメモリ上の純粋関数で行う。拡張は WXT 製で Firebase JS SDK から同じ Firestore に書き込むだけ。`#ラベル` 解析は両方で同じテストケース（`spec/hashtags.json`）を通す。

**Tech Stack:**
- Android: Kotlin 2.x（K2）/ AGP・Gradle 最新安定 / Version Catalog / KSP / Jetpack Compose（BOM）+ Material 3 / Hilt / Navigation 3（`androidx.navigation3` ＋ `lifecycle-viewmodel-navigation3`）/ kotlinx.serialization / Coroutines・Flow / Firebase BoM（Auth, Firestore）/ Credential Manager + Google ID / DataStore Preferences / Glance / java.time
- Android テスト: JUnit4 / kotlinx-coroutines-test / Turbine / Truth / Compose UI Test / Firebase Emulator
- Android 静的解析: Spotless + ktlint（+ Compose ルール `io.nlopez.compose.rules:ktlint`）/ detekt（+ `io.nlopez.compose.rules:detekt`）/ Android Lint / Kotlin `allWarningsAsErrors`
- 拡張: WXT（Vite ベース、MV3）+ TypeScript strict（素の TS、UI フレームワークなし）/ Vitest / oxlint・oxfmt（`@caffelatte23/oxc-config`）
- ルート: mise（`mise.toml`: Node・pnpm・JDK・Firebase CLI）/ pnpm workspace（`extension`, `firebase`）/ lefthook（Git フック）/ `pnpm check`（CI の代わり）

**Spec:** `docs/design.md`（画面: https://claude.ai/artifact/XNVpYyrRaFq4GFHVAdE2gy）

**GitHub:** リポジトリ `caffelatte23/futaba`、Project「Futaba」(https://github.com/users/caffelatte23/projects/1)、Milestone `v1`。Task N ＝ Issue #N（追加の Task 19 のみ Issue #26）。フェーズ M0〜M6 は親 Issue #19〜#25 で、各 Task はその子 Issue。Task 間の前後関係は Issue の「blocked by」で設定済み。

| 担当 | Task | 理由 |

## Global Constraints

- アプリ名表記「Futaba」。applicationId / package: `io.github.caffelatte23.futaba`
- minSdk 26、compileSdk / targetSdk 37（インストール済み `android-37.0`）、JDK 21（mise の temurin-21。Android のビルド成果物のターゲットは各 Task の設定どおり）
- ライブラリは Version Catalog（`android/gradle/libs.versions.toml`）で最新安定版。alpha/beta は使わない（Navigation 3 も stable 版）。Firebase は BoM 経由、KTX モジュールは使わない（本体に統合済み）
- Firebase は Spark（無料）のまま。Cloud Functions・課金必須機能は使わない
- **開発ツール（Node・pnpm・JDK・Firebase CLI・lefthook）はリポジトリの `mise.toml` で固定する。** ユーザーのグローバル mise 設定に同じツールがあっても、プロジェクト側で改めてバージョンを固定する。グローバルインストールや npx に依存しない。新しい CLI が要るときも mise.toml に足す
- **GitHub Actions は使わない**（`.github/workflows/` を作らない）。CI の代わりは lefthook の pre-push で走る `pnpm check`
- **規約の置き場所:** 静的解析で検査できる規約（書式・命名・Compose の作法・未使用・アクセシビリティ・型）は AGENTS.md に書かず、ktlint / detekt / Android Lint / oxlint / tsc の設定に定義する。AGENTS.md には検査できないことだけを書く
- 確認ダイアログを出さない。保存は自動、削除はソフト削除＋5秒の「元に戻す」
- 色: 背景 `#f4f4f0`、文字 `#161616`、補助文字 `#5c5c57`、アクセント `#ffc83d`、カード `#ffffff`。フォント IBM Plex Sans JP（数字・時刻は IBM Plex Mono）。色・文字スタイルは `core/designsystem` の外で直接書かない
- Firestore パス `users/{uid}/notes/{id}`・`users/{uid}/labels/{id}`。フィールド名は `docs/design.md` のデータ節どおり

## Review Focus

1. URL や本文中の `#`（`https://x.com/#a`、`色#123`、`&#123;`）がラベルにならない — Task 4 の `spec/hashtags.json`
2. 空白だけの入力は送信されない（送信ボタン無効） — Task 7 `sendIgnoresBlankText`
3. オフラインで初回起動しても入力が消えない（匿名ログイン前は送信不可、下書きに残る） — Task 5 `draftSurvivesWhenSignedOut`、Task 7 `sendDisabledWithoutUid`
4. 2台目の端末で既に使っている Google アカウントに同期すると、両方のメモが1つにまとまる — Task 13 `collisionMergesAnonymousNotes`
5. 削除→元に戻す→オフライン、でもメモが戻る — Task 6 `deleteThenRestoreKeepsNote`
